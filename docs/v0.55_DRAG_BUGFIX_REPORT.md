# DaniyaSummerPet v0.55 拖拽边缘锁死缺陷 (Edge Lock) 修复报告

本报告详细记录了在 v0.55 阶段发现并解决的桌宠拖拽到屏幕边缘后“锁死”且无法拖离边缘的缺陷排查与修复过程。

---

## 🐞 缺陷现象 (Symptom)
当用户将桌宠达妮娅拖拽到屏幕的最左侧或最右侧边缘松手后，桌宠会顺利吸附吸边并处于 peek 状态。然而，一旦用户再次尝试用鼠标将达妮娅从屏幕边缘拖离到屏幕中央时，**桌宠会瞬间弹回并死死锁在屏幕边缘，无法移开。**

---

## 🔍 根本原因分析 (Root Cause)

通过代码结构审计和实时运行状态流分析，定位到以下三个共同作用导致锁死的核心逻辑缺陷：

1. **Win32 `GetAsyncKeyState` 鼠标释放检测极不稳定**
   - **原逻辑**：在 `src/pet_window.py` 中，存在一个 `_tick_global_click` 计时器（每 80ms 触发一次）。当检测到 `drag_start_global is not None`（处于拖拽中）时，它通过 Windows 底层 Win32 API `ctypes.windll.user32.GetAsyncKeyState(0x01)` 来轮询判断鼠标左键是否已被释放。
   - **问题**：在很多系统环境（例如高刷新率显示器、重度 CPU 渲染占满、触控板/触控手势、虚拟化沙盒环境或多窗口焦点切换时），`GetAsyncKeyState(0x01)` 的硬件状态查询极易出现瞬时为 `0` 的失真。
   - **致命后果**：一旦它返回 `0`，`_tick_global_click` 会在拖拽**还没结束**时提前调用 `handle_release()`，导致拖拽逻辑中途流产，内部拖拽标志 `is_dragging` 被设为 `False`，而 `drag_start_global` 被置为 `None` 并瞬间触发 `snap_and_save` 强行将窗口拉回屏幕边缘。此时，用户虽然仍在物理按住并移动鼠标，但软件已拒绝响应移动事件。

2. **边沿吸附计时器 `_tick_edge_peek` 缺失核心交互状态校验**
   - **原逻辑**：`src/pet_window.py` 中的 `_tick_edge_peek` 每 500ms 执行一次，用于检测桌宠是否需要滑入贴边 peeking 状态。它只检查了 `self.drag_start_global` 是否为空。
   - **问题**：当拖拽状态因上一条原因被提前终止，或者当鼠标按下点击、但位移尚未越过 `drag_threshold` (8像素) 判定为拖拽前，`self.drag_start_global` 的确是 `None`。因此，`_tick_edge_peek` 仍然会疯狂触发，强行通过 `self.move()` 把正在交互中的桌宠吸附回屏幕边缘。

3. **吸附属性动画 (`QPropertyAnimation`) 冲突**
   - **原逻辑**：拖拽释放时，如果开启了回弹动画，`SnapController` 会启动一个 300ms 的位置渐变动画将窗口平滑过渡到吸附点。
   - **问题**：在此 300ms 期间，`_tick_edge_peek` 依然在并发运行，缺少对“吸边动画正在运行中”的卫语句拦截，使得动画路径与吸边动作发生抢占与闪烁。

---

## 🛠️ 修复措施 (Fixes Implemented)

我们在不破坏任何原有特性的前提下，全面用 **Qt 原生跨平台 API** 代替不稳定的底物理轮询，并给事件拦截添加了完整的防护。

### 1. 彻底移除定时器中的拖拽释放校验 (彻底根除因轮询导致的拖拽中断)
修改 `src/pet_window.py` 中的 `_tick_global_click`：
- **原逻辑**：在计时器中轮询检查鼠标左键状态，若检测为未按下，则通过 `handle_release()` 强行中断拖拽。
- **问题**：在各种多模态与性能波动环境下，底层轮询极易发生短暂失真（即使在 Qt 中使用 `QGuiApplication.mouseButtons()` 也无法完全规避瞬时偏差），导致拖动过程中误判并强行将拖拽中断重置为贴边。
- **修复**：**彻底删除了该定时器内的拖拽释放检查代码。**
- **安全性分析**：因为 `PetAvatar` 在鼠标按下时已经调用了 `self.grabMouse()` 独占捕获鼠标，Qt 框架**百分之百能确保** `mouseReleaseEvent` 能够在任何位置（包括超出窗口范围）正确响应并安全释放。因此，定时器轮询释放是完全多余且危险的。删除它能彻底根治拖动中断与锁死缺陷。

### 2. 引入 `is_pressed` 精准跟踪鼠标物理按下状态
在行为检测器 `src/behavior/interaction_detector.py` 中，新增 `is_pressed` 成员变量。当用户物理按下鼠标立刻标为 `True`，物理释放后设为 `False`：
- 在 `handle_press` 阶段：`self.is_pressed = True`
- 在 `handle_release` 阶段：`self.is_pressed = False`

### 3. 给 `_tick_edge_peek` 增加全方位的交互安全卫语句
修改 `src/pet_window.py` 中的 `_tick_edge_peek`：
```python
    def _tick_edge_peek(self) -> None:
        pet_config = self.app_config.get("pet", {})
        if not bool(pet_config.get("edge_peek_enabled", True)):
            self.dock_side = None
            return

        # 精准判定：如果正在拖动、鼠标已经按下、或者回弹渐变动画尚未执行完毕，严禁任何吸附/隐藏回拉逻辑干扰
        is_user_interacting = (
            self.drag_start_global is not None
            or (hasattr(self, "behavior_engine") and (
                self.behavior_engine.detector.is_dragging
                or getattr(self.behavior_engine.detector, "is_pressed", False)
                or (self.behavior_engine.snap_controller._anim is not None and
                    self.behavior_engine.snap_controller._anim.state() == self.behavior_engine.snap_controller._anim.State.Running)
            ))
            or (self.context_menu is not None and self.context_menu.isVisible())
        )
        if is_user_interacting:
            return
```
