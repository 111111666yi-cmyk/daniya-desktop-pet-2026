# v0.7x Backfill And Streaming Plan

Date: 2026-06-11

## Completed Backfills

### Settings Center

- The default display mode is `simple`.
- Simple mode keeps the cloud Provider entry, pet appearance and topmost controls, character selection, user profile and memory, reminders, privacy status, and a read-only voice status.
- Advanced mode reveals local models, multimodal configuration, character-pack editing, raw relationship/event data, system data, file organization, system status, clipboard, focus mode, and diagnostics.
- Switching modes only changes visibility. It does not delete, reset, enable, or disable existing settings.
- High-risk features retain their existing disabled defaults.
- The new `settings_mode` value is normalized and synchronized in the default config and both public app-config seeds.

### User Profile And Relationship State

- User profiles now support an optional `birthday` field containing month and day only.
- Full dates and invalid dates are rejected; no year is stored.
- Old profiles receive an empty birthday at load time.
- Saving a profile preserves unknown existing fields instead of rewriting the file to a fixed schema.
- The existing `relationship` field remains unchanged and is now editable from Settings Center as well as the context-menu profile dialog.
- Existing relationship-state loading already merges missing defaults and preserves unknown fields; regression coverage now locks that behavior.
- Profile, memory, and relationship runtime data remain outside Git and release packages.

## LLM Streaming Decision

Status: `DEFERRED AFTER TECHNICAL REVIEW`.

No streaming runtime flag or partial implementation was added in this phase.

| Question | Current result |
|---|---|
| Does `ChatClient` or `ProviderManager` support streaming? | No. The adapter and all Provider boundaries return one completed string. The Ollama request explicitly uses `stream: false`. |
| Can `speech_filter` process tokens incrementally? | No. It performs whole-response addressing cleanup, expansion removal, response-mode selection, and boundary-aware shortening. |
| Can raw tokens preserve Daniya's voice? | Not reliably. Text shown before final filtering can contain wording that is later removed or rewritten. |
| Can TTS consume streaming tokens safely? | No mainline TTS execution is implemented. The preserved interface must consume only final cleaned text in any future design. |
| Can the bubble update incrementally? | The typewriter can reveal a completed string, but the chat pipeline has no append/replace/cancel protocol for network chunks. |
| Is interruption and fallback defined? | No. Current fallback happens after one completed Provider call fails. There is no partial-output rollback contract. |
| What does history save? | Final engine output after routing and speech filtering. This must remain the rule. |

Implementing raw token display now would expose unfiltered text and then visibly replace it at completion. It would also require cancellation, timeout, fallback, history, and optional voice contracts that do not exist. That risk is larger than this backfill and would weaken the v0.75 speech guarantees.

## Future Streaming Test Plan

A future stage may proceed only after these contracts exist:

1. A Provider-neutral chunk iterator with cancellation and timeout propagation.
2. A bubble API that distinguishes provisional text from committed final text.
3. A final whole-response `speech_filter` pass before history or any voice hook.
4. A rollback rule that removes provisional text when streaming fails and retries non-streaming once.
5. Tests proving raw chunks never enter history, memory, relationship events, or TTS.
6. Tests for cancellation, malformed chunks, partial UTF-8 data, timeout, fallback, and final-text replacement.
7. An experimental flag defaulting to false only when a working implementation exists.
