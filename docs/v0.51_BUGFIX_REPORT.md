### BUG-01：运行目录下存在空 characters 外部文件夹导致启动崩溃
- **严重等级**：P0 (阻塞级)
- **复现步骤**：
  1. 在 `run.bat` 同级目录下新建一个空的 `characters/` 文件夹。
  2. 运行 `run.bat` 或独立 EXE，程序在启动加载角色配置时直接崩溃闪退。
- **根本原因**：`core/character_loader.py` 中的 `character_pack_path` 仅判断了外部根目录 `characters` 是否存在，而没有进一步判断特定角色文件夹（如 `characters/daniya`）是否存在。若存在一个空的外部 `characters` 文件夹，加载器会误认为用户使用外部角色包，并在空目录下查找 `character.yaml` 导致抛出异常崩溃。
- **修改文件**：[core/character_loader.py](file:///C:/Users/23775/Documents/daniya2026523/core/character_loader.py)
- **修复方式**：修改 `character_pack_path`，细化判断逻辑，显式判断具体角色路径 `runtime_root() / "characters" / character_id` 是否存在。若不存在，则平滑降级使用打包内置的角色包目录。
- **回归测试结果**：在同级目录下手动创建空 `characters` 文件夹，运行 `pytest` 及 `run.bat` 均正常启动并加载内置 Daniya 配置。

### BUG-02：打包后未包含 icons 导致设置中心图标全部丢失
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 运行 `pack.bat`。
  2. 启动打包出的 `DaniyaSummerPet.exe` 并打开设置中心。
  3. 观察各个选项卡和按钮，所有 SVG 矢量图标均无法显示。
- **根本原因**：`pack.bat` 之前的 PyInstaller 打包参数漏掉了 `assets/icons/` 目录，导致生成的安装包内完全不包含矢量图标素材。
- **修改文件**：[pack.bat](file:///C:/Users/23775/Documents/daniya2026523/pack.bat)
- **修复方式**：在 `pack.bat` 中加入 `--add-data "assets\icons;assets\icons"` 编译参数，并增加 robocopy 命令在构建 release 发布包时完整复制 `assets/icons`。
- **回归测试结果**：重新打包后，独立 EXE 运行的设置中心选项卡与按钮图标显示完全正常。

### BUG-03：Windows 下多进程/多线程冲突导致设置保存失败崩溃
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 开启软件。
  2. 在设置中心内频繁修改音量或窗口置顶并点击保存。
  3. 在特定并发环境下（如日志流或系统安全工具正在扫描该目录），界面槽会报错 `OSError: [WinError 5] 拒绝访问` 并闪退。
- **根本原因**：在 Windows 操作系统中，若目标文件正在被其他句柄读取（例如日志读取进程或文本编辑器），直接使用原子级 `replace()` 替换正在锁定的文件会触发系统权限冲突报错。
- **修改文件**：
  - [src/settings_manager.py](file:///C:/Users/23775/Documents/daniya2026523/src/settings_manager.py)
  - [src/config_manager.py](file:///C:/Users/23775/Documents/daniya2026523/src/config_manager.py)
- **修复方式**：对 `SettingsManager._save_json_atomic()` 和 `ConfigManager.save_json()` 使用 try-except 对替换操作进行捕获。当 `tmp.replace()` 抛出 `OSError` 时，平滑降级为直接覆盖写入（`write_text`）并清理临时文件，确保保存必定成功。
- **回归测试结果**：使用脚本模拟后台高频读取，设置中心修改保存依然能够稳定落盘，不再闪退。

### BUG-04：未对 API Key 的配置名参数校验导致极端环境下读取崩溃
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 在 `model_profiles.json` 中配置一个空的或未定义的 `api_key_env`。
  2. 打开设置中心加载配置，程序报错闪退。
- **根本原因**：`SettingsManager.current_api_key()` 直接在 `dotenv_values()` 加载时对传入参数进行读取，未考虑 `env_key_name` 传入为空字符串或非空类型的场景，导致特定环境下抛出空指针或 Key 异常。
- **修改文件**：[src/settings_manager.py](file:///C:/Users/23775/Documents/daniya2026523/src/settings_manager.py)
- **修复方式**：在函数头部增加 `if not env_key_name: return ""` 前置卫语句防护，如果传入为空或无效，则直接返回空字符串。
- **回归测试结果**：将配置置空，设置中心各选项卡完美解析。

### BUG-05：本地离线模式下网络异常或缺 Key 时 fallback 显示了错误文案
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 清空本地 API Key 且不配置环境变量，或者启用“本地模式”。
  2. 给桌宠发送一条消息。
  3. 桌宠气泡显示的是 *“达妮娅刚刚走神了一下……”*（报错占位文案）而不是温馨的离线提示文案。
- **根本原因**：在本地离线模式下，`ChatClient.reply()` 调用 `local_reply` 时漏掉了 `missing_key=True` 参数，致使 `local_reply` 默认走 `api_error=True` 的分支，错误展示了 API 连线发生故障时的报错气泡。
- **修改文件**：[src/chat_client.py](file:///C:/Users/23775/Documents/daniya2026523/src/chat_client.py)
- **修复方式**：在 `ChatClient.reply()` 的本地模式分支中，调用 `self.local_reply(missing_key=True)`，保证在无 Key 时明确提示温馨的本地陪伴文案。
- **回归测试结果**：处于离线状态时，桌宠发送出正确的友好本地温馨陪伴信息。

### BUG-06：动作帧图片丢失时 manifest fallback 路径失效引发空白渲染
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 在 `actions.yaml` 动作帧中指向一个不存在的 PNG 图像。
  2. 触发对应动作（例如 `remind`）。
  3. 桌宠窗口立绘在动画播放时显示为白色方块或抛出资源未找到错误。
- **根本原因**：当检测到自定义动作帧图片缺失时，`ActionManifest.get_fallback_frames` 在执行 fallback 回退到 placeholder 文件路径时，未使用 `resource_path` 解析绝对路径，导致 PySide6 QPixmap 加载相对路径时失败。
- **修改文件**：[src/action_manifest.py](file:///C:/Users/23775/Documents/daniya2026523/src/action_manifest.py)
- **修复方式**：在 `_verify_frames` 中，如果需要回退至内置 placeholder 帧，使用 `resource_path("assets", "placeholder", frame)` 并转换为字符串绝对路径，确保系统加载一定能获取到本地物理文件。
- **回归测试结果**：故意移除部分非核心动作文件，触发对应动作时，完美 fallback 渲染备用正常立绘。

### BUG-07：右键菜单 / 设置中心加载因频繁磁盘 I/O 检查产生卡顿
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 开启程序，频繁右键点击立绘弹出上下文菜单。
  2. 在 Windows 上可以明显感知到每次右键均有几十毫秒的顿挫与卡顿（对于高刷屏尤为明显）。
- **根本原因**：每次触发右键菜单弹出或打开设置中心时，都会调用 `icon_utils.py` 中的 `icon` 载入方法。该方法没有进行缓存，导致每次都需要在物理磁盘上执行 `icon_path.exists()` 检查，在 Windows I/O 调用下耗时较多，阻塞了主 GUI 线程。
- **修改文件**：[src/icon_utils.py](file:///C:/Users/23775/Documents/daniya2026523/src/icon_utils.py)
- **修复方式**：在 `src/icon_utils.py` 中增加了一个全局的内存缓存字典 `_ICON_CACHE`，对已经解析出的 `QIcon` 实例依据 `icon_key` 与 `root` 做全局缓存。二次使用时从内存中秒回，杜绝物理磁盘检索。
- **回归测试结果**：右键点击和设置中心打开毫无延迟，菜单秒开，顺滑自如。

### BUG-08：事件日志格式迁移至 JSONL 后选项卡无法解析且历史对话不支持框选复制
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 打开设置中心，切换至“数据与系统”或原“关系与事件”页面。
  2. 观察到“事件日志”文本框显示为空白或提示解析失败。
  3. 打开“历史记录”弹窗，历史消息不支持用鼠标划选，无复制按钮。
- **根本原因**：物理交互事件存储结构在之前的优化中升级为行级 JSONL 存储（`event_log.jsonl`），但是设置中心的刷新函数 `RelationshipStateViewer.status()` 依然按照旧版本的单一大 JSON 数组逻辑进行读取加载，导致解析异常。
- **修改文件**：
  - [src/relationship_state_viewer.py](file:///C:/Users/23775/Documents/daniya2026523/src/relationship_state_viewer.py)
  - [src/menu_manager.py](file:///C:/Users/23775/Documents/daniya2026523/src/menu_manager.py)
- **修复方式**：
  1. 修改 `RelationshipStateViewer.status()`，调用核心 `core.memory_engine.load_event_log()` 标准加载器来兼容读取 JSON 和 JSONL 格式，恢复事件显示。
  2. 升级 `HistoryDialog` 将展示对话的文本控件属性修改为 `TextSelectableByMouse`，并增加“一键复制当次对话”按钮，丰富复制体验。
- **回归测试结果**：设置中心事件日志恢复实时滚动，历史对话可以拖拽选中复制，且复制按钮运行完美。

### BUG-10：打包生成的 ZIP 解压后无父级文件夹污染目录
- **严重等级**：P1 (严重级)
- **复现步骤**：
  1. 运行 `pack.bat`。
  2. 观察生成的 `.zip` 压缩文件解压时的行为：所有子文件和 DLL 会直接解压平摊在当前解压目录，无统一文件夹包裹。
- **根本原因**：`pack.bat` 内部在调用 Powershell `Compress-Archive` 命令时，源路径使用了 `release\%PACKAGE_NAME%\*` (带有通配符的内部平铺路径)，导致生成的 zip 没有包含根文件夹。
- **修改文件**：[pack.bat](file:///C:/Users/23775/Documents/daniya2026523/pack.bat)
- **修复方式**：将打包命令中压缩的源路径修改为 `release\%PACKAGE_NAME%` 顶级文件夹本身。
- **回归测试结果**：打包出的 ZIP 文件解压时会自动建立 `DaniyaSummerPet-v0.51-win-x64/` 顶级根文件夹包裹，文件架构非常干净。
