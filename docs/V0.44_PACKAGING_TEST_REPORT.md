## 8. Resource Path Fixes

Existing `src/utils.py` already provides:

- `bundled_root()`
- `runtime_root()`
- `resource_path()`

v0.44 updates:

- `core/character_loader.py` now resolves character packs from exe-adjacent `characters/` first, then bundled resources.
- `core/memory_engine.py` writes runtime relation data under `runtime_root()/data/daniya_relation`.
- `core/relationship_engine.py` writes runtime relationship state under `runtime_root()/data/daniya_relation`.

This keeps public packaged resources readable while keeping runtime data outside the bundled `_internal` resource area.

## 17. Remaining Issues

- User follow-up reported a desktop pet crash and unclear summon entry. Root cause was confirmed: `_print_render_debug()`, `contextMenuEvent()`, and `icon_path()` had slipped outside the `PetWindow` class during the previous safety patch, so first image render could raise `AttributeError`. This is fixed and `pytest -q` is back to passing.
- The package was also adjusted to ship clean default config from `config/app_config.example.json` and `config/api_config.example.json`, rather than local runtime coordinates/input-box state.
- A visible right-click menu action was added: `基础 / 召唤到鼠标位置`. The older experimental toggle `基础 / 宠物功能 / 左键点击桌面召唤` remains available but is no longer the only discoverable summon path.
- Packaged GUI interaction was smoke-tested for startup and visibility after the fix. Full manual click-through of settings center, Daniya read-only window, input box, bubble, and typewriter should still be repeated by the user before any future public Release.
- The wrong API key test verified startup safety with a bad key. A packaged GUI send/test-connection click should be manually checked before v0.49 Release.
- v0.44 is a packaging test only; no GitHub Release or tag was created.

v0.44 packaging test passes for local exe/zip generation, startup, resource fallback, zip safety, Git safety, and the post-feedback crash/summon fixes.
